## P0 — Deployment blockers

### P0-1 (security) `/cache` router mounted with ZERO auth — unauthenticated destructive DELETE
`routes/cache.py` builds `APIRouter(prefix="/cache")` with no auth dependency,
and `app.py:888` mounts it without `mode`. Every other admin router is gated by
`require_active_admin`. In company mode any unauthenticated caller can hit
`GET /cache/stats` and, worse, `DELETE /cache/documents[?ticker=]`, wiping the
instance-wide document cache (unauthenticated destructive action / cache-DoS).
Fix: gate the router with `build_require_active_admin(..., mode=mode)`, add a
`mode` param, pass `mode=mode` at the mount.

### P0-2 (reliability) Blocking SDK calls run on the asyncio event loop
`connectors/transports/python_lib.py:171` does `result = method(**bound)`
synchronously inside `async def call_tool`. For sync SDKs (EODHD, Mediastack,
firecrawl) the full blocking network call executes on the loop, stalling every
concurrent SSE stream/runner. This is the mechanism behind the 2026-06-21 v3
EODHD 54-minute hang. PR #265 patched the v3 runner's dispatch, but the
transport itself — used by EU/MB runners and all connector tool calls — is still
unbounded. Fix: `await asyncio.wait_for(asyncio.to_thread(method, **bound), timeout=...)`
for non-awaitable results. Plus `eodhd_extended` issues un-timed `requests.get`.

## P1 — CI green / correctness

### P1-1 (bug) Alembic ORM drift: `mr_dashboard_cache.provenance` missing `server_default`
`db/models/dashboard.py:177` declares `provenance` with Python `default="live"`
only; the creating migration set `server_default=sa.text("'live'")`. Autogenerate
emits a non-empty diff → `test_alembic_autogenerate_is_clean` fails. The sibling
`RsDashboardCache.provenance` was already fixed; a code comment flags this one as
the deliberate un-fixed drift. Fix: add `server_default="live"`. No new migration.

### P1-2 (test bug) `test_value_series_returns_points` seeds stale dates
`tests/test_routes/test_portfolio_value_series_route.py` seeds quotes dated
2026-05-01/05-08; the route uses real `datetime.now(UTC)` (2026-06-21), so the
`1m` window (start 2026-05-22) excludes all rows → 0 points. Production query is
correct. Fix: anchor seed dates to `now - 14d`/`now - 7d`.

### P1-3 (test infra) Frontend AbortSignal realm mismatch → vitest exit 1
jsdom's global `AbortSignal` is not `instanceof` undici's `AbortSignal`, so
react-router's `createClientSideRequest` → `new Request(url, {signal})` throws an
async unhandled rejection. Surfaces in `SettingsShellBlocker.test.tsx` and
`SettingsPage.test.tsx`. Tests "pass" but the suite exits non-zero. Fix: align
the globals in `setupTests.ts`.

### P1-4 (test infra) 3 collection errors in `test_routes_notifications.py`
`NoReferencedTableError: repo_items.mb_v2_report_id` can't find table
`report_mb`. FK target table not in the mapper registry for that test's import
ordering. Fix: ensure the `report_mb` model is imported by the metadata used in
those tests (model-registry import-ordering bug).

### P1-5 (security, defense-in-depth) Owner-unaware service helpers
`services/chat_sessions.py:109` (`ensure_titled`) and `services/repo.py:78`
(`save_to_repo`) do `db.get(...)` with no owner filter. Not currently
exploitable (callers pre-check), but foot-guns. Fix: add `user_id` filtering.
