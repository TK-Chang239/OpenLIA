# Phase 1.5: User Template Upload Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users upload custom report structures (markdown / docx / txt) that drive the v2.3 equity-research engine the same way the built-in `TemplateSpec`s do. Closes the loop opened by Phase 1: the `TemplateSpec` rails were built explicitly so user-uploaded templates could replace `get_builtin(report_type)` at run-launch time.

**Architecture:** Most of the infrastructure already exists from PR 13 (May 2026) — a `report_templates` SQLAlchemy model, an Alembic migration, ingest/parse/compile services, and full CRUD endpoints at `/api/report-templates`. The catch: that infrastructure was built for the v2 engine and the existing `compile_template_spec` emits v2-shaped JSON (`body_sections`, `voice`, `word_target`, `dispatch_tier`, `cover_bindings`, etc.). v2.3's `TemplateSpec` is a different schema. Phase 1.5 adds a parallel v2.3-aware path on top of the existing infrastructure:

1. A new `compile_v23_spec` service maps the existing `ParsedTemplate` (sections + frontmatter) onto a v2.3 `TemplateSpec` dict.
2. A new `POST /api/report-templates/v23/parse` endpoint exposes the v2.3 compile path for the upload UI to preview.
3. `v2_3_run_service.start_run` accepts an optional `template_id` in the request body; when present, loads the row from `report_templates`, validates the JSON as a `TemplateSpec`, and uses it as `state.template`. When absent, falls back to `get_builtin(report_type)` (existing behavior).
4. Frontend adds a template-upload modal that uses the existing ingest + new v23/parse endpoints + existing CRUD-save, plus a picker on the v2.3 launch flow that threads the chosen `template_id` into the run-launch request.

The existing v2 routes / services / model / migration are not touched — they continue to serve the v2 engine. Users with a v2-shaped template in the table will get a 422 if they try to use it via v2.3; the picker can list-all (no schema discrimination in v1) and the user re-uploads via the v2.3 flow if needed.

**Tech Stack:** Python 3.13 + Pydantic v2 + SQLAlchemy + FastAPI on the backend; TypeScript + React + Vite on the frontend. Test runners: `uv run pytest` for backend, `npm test` (vitest) for frontend.

**Scope decisions locked up front:**
- **One PR with backend + frontend.** Phase 1.5 ships as a single feature merge; backend-only is invisible to users. Frontend follows backend tasks in sequence.
- **Markdown is the primary input format.** docx and txt are already supported via the existing `/ingest` endpoint (it converts to markdown); v2.3 parse consumes the converted markdown. No new format-parsing code in this phase.
- **Reuse existing CRUD endpoints** (`/api/report-templates`) for save/list/get/delete. Only the parse endpoint gets a v2.3 variant; the save shape is the same generic `{ name, template_spec, source_markdown }`.
- **No schema-version column** on the `report_templates` table. The runtime validates the stored JSON as v2.3 at start-run time; mismatched rows raise 422 with a clear message. Phase 1.5b can add filtering / migration if real user-feedback warrants.
- **No user-edit-in-place flow.** Users re-parse and re-save. Upload-replace is the minimum-viable UX.
- **The conversion path is deterministic.** Reuses the existing pure-Python `parse_template` + the new `compile_v23_spec`. No LLM call at upload time (the existing v2 conversion prompt is for a different flow and not required here). This keeps the upload fast and the parse output reviewable / editable.
- **Built-ins coexist.** The picker on the v2.3 launch flow shows user templates + a "Default (report-type built-in)" option. When the user picks the default, `template_id` is omitted from the run request and the wiring falls back to `get_builtin`.

**Out of scope (Phase 1.5):**
- Schema-version column / v2 vs v2.3 filtering server-side (defer to user-feedback signal)
- Edit-in-place for stored templates (replace via re-upload is the v1 UX)
- LLM-driven conversion (deterministic parser is sufficient for v1)
- Template sharing across users (per-owner scoping only)
- ChartType enum widening (separate phase — needs renderer story)

### Step 4: Implement `compile_v23_spec`

Create `packages/server/src/openlia_server/services/template_compile_v23.py`:

```python
"""Compile a `ParsedTemplate` into a v2.3 `TemplateSpec` dict.

The parser (template_parser.py, pre-existing) splits markdown into a
preamble + per-section list with optional YAML frontmatter blocks.
This service maps that shape onto the v2.3 ``TemplateSpec`` schema
(`packages/core/src/openlia/llm/runtime/report_v2_3/templates/spec.py`).
The returned dict is JSON-serialisable and ready for
``ReportTemplate.template_spec_json`` storage; callers should validate
it via ``TemplateSpec.model_validate`` before persisting so bad shapes
surface to the user immediately.

Mapping:
- ``ParsedSection.id`` → ``SectionSpec.id`` (slug; already validated by parser)
- ``ParsedSection.title`` → ``SectionSpec.title``
- ``ParsedSection.brief`` → ``SectionSpec.intent`` (with title-based fallback when empty)
- ``ParsedSection.frontmatter["methodology_hints"]`` → ``SectionSpec.methodology_hints``
- ``document_frontmatter["name"]`` → ``TemplateSpec.name`` (else ``fallback_name``)
- ``document_frontmatter["shape_description"]`` → ``TemplateSpec.shape_description``
  (else a generated fallback so the required field is populated)
- ``document_frontmatter["ticker_anchored"]`` → ``TemplateSpec.ticker_anchored``
- ``document_frontmatter["default_length"]`` → ``TemplateSpec.default_length``
- ``TemplateSpec.template_id`` is generated from a sanitized name + a short uuid

LLM-driven conversion is intentionally not used — the parser is
deterministic, the schema is permissive enough that most reasonable
markdown structures map cleanly, and round-tripping the original
markdown stays trivially possible.
"""

from __future__ import annotations

import re
import uuid
from typing import Any

from openlia_server.services.template_parser import ParsedTemplate

_SLUG_RE = re.compile(r"[^a-z0-9]+")


def _slugify(text: str) -> str:
    s = _SLUG_RE.sub("_", text.lower()).strip("_")
    return s or "template"


def _build_template_id(name: str) -> str:
    """Generate a stable-looking but unique template_id from the name.
    Format: `<slug>_<8-char-suffix>` — passes TemplateSpec's slug regex
    and guarantees uniqueness for the row even when two templates share
    a display name."""
    return f"{_slugify(name)}_{uuid.uuid4().hex[:8]}"


def _section_intent(brief: str, title: str) -> str:
    if brief.strip():
        return brief.strip()
    return f"Cover {title}."


def _section_methodology_hints(frontmatter: dict[str, Any]) -> list[str]:
    raw = frontmatter.get("methodology_hints")
    if isinstance(raw, list):
        return [str(item) for item in raw if str(item).strip()]
    return []


def compile_v23_spec(
    parsed: ParsedTemplate,
    *,
    fallback_name: str,
) -> dict[str, Any]:
    """Return a v2.3 ``TemplateSpec``-shaped dict from a parsed markdown
    template. Raises ``ValueError`` when the parse yielded no sections —
    ``TemplateSpec.sections`` requires ``min_length=1``."""
    if not parsed.sections:
        raise ValueError(
            "Template needs at least one section (use H1 or H2 headings)."
        )
    doc_fm = parsed.document_frontmatter or {}
    name = str(doc_fm.get("name") or fallback_name)
    sections = [
        {
            "id": s.id,
            "title": s.title,
            "intent": _section_intent(s.brief, s.title),
            "methodology_hints": _section_methodology_hints(s.frontmatter),
        }
        for s in parsed.sections
    ]
    out: dict[str, Any] = {
        "template_id": _build_template_id(name),
        "name": name,
        "shape_description": str(
            doc_fm.get("shape_description")
            or f"Custom template: {name}."
        ),
        "ticker_anchored": bool(doc_fm.get("ticker_anchored", True)),
        "sections": sections,
    }
    if "default_length" in doc_fm:
        out["default_length"] = str(doc_fm["default_length"])
    return out
```

```python
@router.post("/v23/parse", response_model=V23ParseOut)
def v23_parse(
    payload: V23ParseIn,
    _user: User = require_auth,
) -> V23ParseOut:
    """Parse markdown into a v2.3 TemplateSpec dict for preview.

    The endpoint always returns 200 — schema validation errors come
    back in `validation_errors` so the upload UI can render them
    inline next to the parsed structure rather than as an HTTP error."""
    parsed = parse_template(payload.markdown)
    try:
        spec_dict = compile_v23_spec(parsed, fallback_name=payload.name)
    except ValueError as err:
        return V23ParseOut(template_spec={}, validation_errors=[str(err)])
    errors: list[str] = []
    try:
        V23TemplateSpec.model_validate(spec_dict)
    except ValidationError as err:
        errors = [
            f"{'.'.join(str(p) for p in e['loc'])}: {e['msg']}"
            for e in err.errors()
        ]
    return V23ParseOut(template_spec=spec_dict, validation_errors=errors)
```

def _resolve_template(
    db: Session,
    user_id: str,
    report_type: ReportType,
    template_id: str | None,
) -> TemplateSpec:
    """Return the TemplateSpec for this run.

    - ``template_id is None`` → built-in for the ``report_type``
    - ``template_id`` set → load from ``report_templates``, owner-scoped,
      validate as a v2.3 ``TemplateSpec``. 404 if not owned by the
      caller; 422 if the stored JSON does not validate (e.g. legacy v2
      shape).
    """
    if template_id is None:
        return get_builtin(report_type)
    row = db.get(ReportTemplate, template_id)
    if row is None or row.user_id != user_id:
        raise HTTPException(status_code=404, detail="template not found")
    try:
        return TemplateSpec.model_validate(row.template_spec_json)
    except ValidationError as err:
        raise HTTPException(
            status_code=422,
            detail={
                "message": (
                    f"Template {template_id} is not a valid v2.3 TemplateSpec. "
                    "Re-upload via the v2.3 template flow."
                ),
                "errors": [
                    f"{'.'.join(str(p) for p in e['loc'])}: {e['msg']}"
                    for e in err.errors()
                ],
            },
        ) from err

```tsx
import { useState } from "react";

import {
  parseMarkdownV23,
  saveReportTemplate,
  type TemplateSpec,
} from "../../api/report-templates";

export interface V23TemplateUploadModalProps {
  open: boolean;
  onSaved: (templateId: string) => void;
  onClose: () => void;
}

export function V23TemplateUploadModal({
  open,
  onSaved,
  onClose,
}: V23TemplateUploadModalProps): JSX.Element | null {
  const [markdown, setMarkdown] = useState("");
  const [name, setName] = useState("Untitled template");
  const [parsed, setParsed] = useState<TemplateSpec | null>(null);
  const [errors, setErrors] = useState<string[]>([]);
  const [busy, setBusy] = useState(false);

  if (!open) return null;

  async function handleParse() {
    setBusy(true);
    try {
      const result = await parseMarkdownV23(markdown, name);
      if (result.validation_errors.length > 0) {
        setParsed(null);
        setErrors(result.validation_errors);
      } else {
        setParsed(result.template_spec as TemplateSpec);
        setErrors([]);
      }
    } finally {
      setBusy(false);
    }
  }

  async function handleSave() {
    if (!parsed) return;
    setBusy(true);
    try {
      const saved = await saveReportTemplate({
        name,
        template_spec: parsed,
        source_markdown: markdown,
      });
      onSaved(saved.id);
    } finally {
      setBusy(false);
    }
  }

  return (
    <div role="dialog" aria-modal="true" className="modal-overlay">
      <div className="modal">
        <h2>Upload v2.3 template</h2>
        <label>
          Template name
          <input value={name} onChange={(e) => setName(e.target.value)} />
        </label>
        <label>
          Markdown
          <textarea
            aria-label="Markdown"
            rows={12}
            value={markdown}
            onChange={(e) => setMarkdown(e.target.value)}
          />
        </label>
        <div className="actions">
          <button onClick={handleParse} disabled={busy || !markdown}>Parse</button>
          <button onClick={handleSave} disabled={busy || !parsed}>Save</button>
          <button onClick={onClose}>Cancel</button>
        </div>
        {errors.length > 0 && (
          <ul className="errors">
            {errors.map((err) => (
              <li key={err}>{err}</li>
            ))}
          </ul>
        )}
        {parsed && (
          <div className="preview">
            <h3>{parsed.name}</h3>
            <p>{parsed.shape_description}</p>
            <ol>
              {parsed.sections.map((s) => (
                <li key={s.id}>{s.title}</li>
              ))}
            </ol>
          </div>
        )}
      </div>
    </div>
  );
}
```
