# Report Rendering Pipeline Design

Transforms LLM-generated report content into professional HTML documents viewable in FileViewer, exportable as PDF. Reports target the visual quality of top investment bank research reports.


## Pipeline Overview

```
LLM generation (single-pass template fill + data tool calls)
    |
Report schema JSON (canonical storable representation)
    |
React report renderer (styled HTML with interactive charts/tables)
    |
FileViewer (in-app viewing)
    |
Headless browser (PDF export on demand)
```

The LLM receives a JSON framework template (per-department, with section structure and guiding instructions), fetches data via tool calls, and fills the template in a single pass. The filled template is the report schema — a self-contained JSON document with all text, chart data, table data, and metadata needed to render the report without re-running the LLM.

The React report renderer reads the schema and renders each block as a component. PDF export runs the rendered HTML through Playwright to produce a visually identical PDF.


## Template-Fill Architecture

### Framework Template (input to LLM)

Each department has a JSON framework template defining section structure and instructions. The LLM receives this template and fills it in.

```json
{
  "schema_version": "1.0",
  "department": "stock_research",
  "cover": {
    "instructions": "Fill in report metadata and 3-5 key metrics the reader should see immediately.",
    "title": null,
    "subtitle": null,
    "ticker": null,
    "tagline": null,
    "key_metrics": [],
    "stats_panel": []
  },
  "sections": [
    {
      "id": "financial_overview",
      "title": "Financial Overview",
      "instructions": "Analyze the company's latest financial statements. Cover revenue, earnings, margins, and cash flow. How do current results compare to prior quarters and consensus estimates? Use charts to show trends and tables for statement summaries.",
      "blocks": []
    },
    {
      "id": "competitive_landscape",
      "title": "Competitive Landscape",
      "instructions": "Who are the main competitors? How does the company's market share, growth rate, and margins compare? A comparison table is useful here.",
      "blocks": []
    }
  ]
}
```

The `instructions` field is consumed by the LLM but stripped from the final output. The LLM fills in `blocks` arrays with content blocks (text, charts, tables) and populates the cover fields.

### Single-Pass Generation

The LLM fills the entire template in one call to maintain narrative continuity and cross-references across sections. Section-by-section generation was considered but rejected because it fragments the writing and prevents the LLM from referencing earlier analysis in later sections.

Generation flow:
1. Server builds the template from the department's framework file, applying user customizations (enabled/disabled sections, custom sections, length preference)
2. LLM receives the template + available data tools
3. LLM makes data tool calls to fetch needed information
4. LLM fills the entire template — cover, all sections, all blocks
5. Server validates and stores the completed schema
6. Frontend renders the report in FileViewer

### Content Decisions

The LLM is the analyst — it decides what charts, tables, and visualizations to include, what type to use, and what data goes in them. The frontend is the renderer — it applies the theme, handles interactivity, and manages responsive layout. The frontend never needs to understand financial content to decide what to visualize.

| Decision | Owner |
|----------|-------|
| Whether to include a chart | LLM |
| What chart type to use | LLM |
| What data goes into the chart | LLM |
| Chart title and axis labels | LLM |
| Whether to group elements side-by-side | LLM |
| Row styles and cell formatting rules | LLM |
| Colors, fonts, sizing, spacing | Frontend (theme) |
| Interactive features (sort, hover, expand) | Frontend |
| Responsive behavior | Frontend |
| PDF page breaks | Frontend |


## Report Schema

The canonical JSON representation stored in the database. Fully self-contained — all text, chart data, table data, section structure, cover metadata, layout hints, and page furniture.

### Schema Rules

- **Flat section list** — sections contain an ordered list of blocks. No deeper nesting beyond groups.
- **Groups are blocks** — a `group` block contains child blocks laid out in N columns.
- **Self-contained** — every chart and table carries its own data. No external data references needed to render.
- **Text blocks are markdown** — the renderer converts markdown to styled HTML.
- **Page furniture is server-populated** — not filled by the LLM. Applied from default config.
- **Schema version** — allows future evolution without breaking saved reports.
- **Instructions stripped** — the `instructions` field from the framework template is removed before storage.


## Block Types

### Text Block

```json
{"type": "text", "content": "Markdown content here..."}
```

Rendered as styled HTML from markdown. Supports bold, italic, bullet lists, numbered lists, inline code, and links.

### Table Block

```json
{
  "type": "table",
  "title": "Table title",
  "headers": [
    {"key": "col_id", "label": "Display Name", "align": "left|center|right", "sortable": true}
  ],
  "rows": [
    {"col_id": "value", "_row_style": "default|subtotal|total|header_group"}
  ],
  "cell_format": {
    "col_id": {"rule": "negative|positive|directional|bold|muted"}
  },
  "footnotes": ["Source attribution", "Methodology note"],
  "options": {}
}
```

**Interactive features (HTML view only):**
- Column sorting: click header to toggle ascending/descending (on columns with `sortable: true`)
- Search: optional search input above table, filters rows by text match
- Expandable rows: if a row has a `_details` field, clicking expands an additional content row beneath

**Row styles:**
- `default` — normal row
- `subtotal` — shaded background (`--report-bg-elevated`), semi-bold text
- `total` — bold text, 2px top border, heavier shading
- `header_group` — section label row spanning all columns, muted background

**Cell format rules** (applied via the `rule` field):
- `negative` — `--report-negative` color when value parses as negative or has `-` prefix
- `positive` — `--report-positive` color when positive
- `directional` — `--report-negative` if negative, `--report-positive` if positive, `--report-neutral` if zero
- `bold` — bold font weight unconditionally
- `muted` — `--report-text-secondary` color

**Footnotes:** Rendered as small-print text directly beneath the table, outside the scrollable/sortable area.

### Metric Cards Block

```json
{
  "type": "metric_cards",
  "metrics": [
    {"label": "Revenue", "value": "$124.3B", "delta": "+31.1%", "delta_direction": "up"},
    {"label": "Net Income", "value": "$36.3B", "delta": "+53.8%", "delta_direction": "up"}
  ]
}
```

Horizontal row of equal-weight stat cards. Delta direction controls color (up = positive, down = negative).

### Group Block

```json
{
  "type": "group",
  "columns": 2,
  "blocks": [...]
}
```

Lays out child blocks side by side in N columns.

**Height normalization rules:**

| Scenario | Behavior |
|----------|----------|
| All charts | All charts share the same height (tallest chart's natural height, or default if all are small) |
| All tables | Each table grows to natural height. No normalization. |
| Mixed (chart + table) | Charts get a fixed height (default medium). Tables grow naturally. Top-aligned. |
| Chart + metric cards | Metric cards top-aligned, chart fills remaining height |

### Chart Blocks

All chart blocks share a common structure:

```json
{
  "type": "<chart_type>",
  "title": "Chart title",
  ...chart-specific data fields...,
  "options": {
    "height": "small|medium|tall",
    "show_legend": true,
    "show_grid": true
  }
}
```

Chart height values: `small` (200px), `medium` (300px, default), `tall` (400px). The group normalizer may override individual heights to match siblings.

## Additional Block Types

### Key Finding Block

A highlighted callout block for important conclusions or discoveries. Visually distinct from body text — accent left border, slightly larger text, elevated background.

```json
{
  "type": "key_finding",
  "content": "iPhone revenue grew 49.3% YoY, the strongest growth since 2021, driven by iPhone 16 Pro demand in emerging markets."
}
```

The LLM places these between sections or within sections to break up text and highlight the most important takeaways.

### Rating Badge Block

Displays analyst-style rating badges and sector tags inline in the report.

```json
{
  "type": "rating_badge",
  "rating": "Overweight",
  "previous_rating": "Equal Weight",
  "change_date": "2026-04-11"
}
```

Rendered as a colored pill badge: green for positive ratings (Buy, Overweight), yellow for neutral (Hold, Equal Weight), red for negative (Sell, Underweight). Shows the previous rating with a strikethrough if changed.

### Sparkline Table Extension

Tables support an optional sparkline column. When a header has `"sparkline": true`, the cell value is an array of numbers rendered as a tiny inline SVG line chart using ECharts in compact mode.

```json
{
  "type": "table",
  "title": "Revenue by Segment",
  "headers": [
    {"key": "segment", "label": "Segment", "align": "left"},
    {"key": "revenue", "label": "Q1 2026", "align": "right"},
    {"key": "trend", "label": "5Q Trend", "align": "center", "sparkline": true}
  ],
  "rows": [
    {"segment": "iPhone", "revenue": "$69.1B", "trend": [46.2, 42.3, 48.8, 56.1, 69.1]},
    {"segment": "Services", "revenue": "$26.3B", "trend": [20.8, 21.2, 22.1, 24.3, 26.3]}
  ]
}
```

Sparklines are tiny (60px wide, 20px tall), no axes, no labels — just the trend shape. Color follows the direction: upward trend uses `--report-positive`, downward uses `--report-negative`.


## Cover Block

The cover renders at the top of every report with two distinct visual zones:

**Key metrics** — a horizontal row of large stat cards (3-5 headline numbers). For high-impact numbers the reader should see first.

```json
"key_metrics": [
  {"label": "Price", "value": "$198.50", "delta": "+2.3%", "delta_direction": "up"},
  {"label": "Market Cap", "value": "$3.02T"}
]
```

**Stats panel** — a compact two-column grid with smaller typography inside a bordered box. For dense metadata the reader scans (rating, target price, sector, exchange, etc.).

```json
"stats_panel": [
  {"label": "Rating", "value": "Overweight"},
  {"label": "Target Price", "value": "$225.00"},
  {"label": "Sector", "value": "Technology"}
]
```

Cover layout: title and subtitle left-aligned, tagline below in italic, key metrics as horizontal cards, stats panel as bordered grid below or right-aligned. Thin divider between cover and first section.


## Global Page Furniture

Configured once at the `ReportRenderer` level, not by the LLM. Populated server-side from default config.

```json
"page_furniture": {
  "header": {
    "left": "OpenLIA",
    "right": "Stock Research Department"
  },
  "footer": {
    "left": "Generated Apr 11, 2026",
    "center": "Page {page}",
    "right": "For internal use only"
  },
  "disclaimer": "This report is generated by AI and should not be considered financial advice. Verify all data independently before making investment decisions."
}
```

**In HTML view:**
- Header: subtle fixed bar at the top of the report content area (inside the report, not the FileViewer header)
- Footer: rendered at the bottom of the report
- Disclaimer: full-width block at the very end
- Scroll-tracking section indicator in FileViewer sidebar highlights the current section

**In PDF:**
- Header and footer repeat on every page via Playwright's `headerTemplate` / `footerTemplate`
- `{page}` token replaced with actual page number
- Disclaimer on the final page


## Streaming During Generation

Single-pass generation means the entire report is produced in one LLM call. The user sees a loading state until the full report is ready.

**SSE events:**

| Event type | Payload | When |
|-----------|---------|------|
| `report:generating` | `{department, section_titles}` | Generation begins |
| `report:progress` | `{status: "fetching_data"}` or `{status: "writing"}` | Phase updates |
| `report:complete` | `{report_id, schema}` | Full report ready |
| `report:error` | `{error}` | Generation failed |

**Frontend during generation:**
- FileViewer opens with loading state: report title, section list as grayed-out placeholders, animated progress bar
- Phase indicator: "Fetching data..." then "Writing report..."
- On complete: full report renders, download button activates
- On error: error message with "Retry" button to regenerate the entire report


## PDF Export Pipeline

PDF is generated server-side via Playwright when the user clicks "Download as PDF."

**Flow:**

```
POST /api/reports/{id}/export/pdf
    |
Server loads report schema from database
    |
Server-side renders report HTML (same React components, static HTML string)
    |
Playwright opens HTML in headless Chromium
    |
Playwright prints to PDF
    |
PDF returned as file download
```

**Page settings:**

| Setting | Value |
|---------|-------|
| Page size | A4 (210mm x 297mm) |
| Margins | Top: 20mm, Bottom: 25mm, Left: 20mm, Right: 20mm |
| Orientation | Portrait |
| Print background | Yes |

**Page breaks:**
- Each section starts on a new page (`page-break-before: always`)
- Charts and tables avoid mid-element breaks (`break-inside: avoid`)
- Groups stay together (`break-inside: avoid`)
- Long tables break between rows with header repeated (`thead { display: table-header-group }`)

**Charts in PDF:** ECharts in SVG rendering mode outputs vector graphics, which Chromium renders natively to PDF — sharp at any zoom level.

**Dark mode:** PDF always uses light mode regardless of app theme setting.

**Performance:** Playwright instance kept warm (reused across export requests). Typical export: 2-5 seconds. Frontend shows loading indicator during generation.

**DOCX export:** Deferred to a future version. v1 offers PDF only.

## Visual Polish (v1)

Features that elevate the report from functional to commercial-grade.

### Gradient Fills on Charts

Area charts and the area beneath line charts use a gradient fill that fades from the line color (at the top) to transparent (at the bottom). Configured in the ECharts theme — no schema change needed. Applies to `line_chart`, `area_chart`, and the line series in `combo_chart`.

### Micro-Animations (Framer Motion)

All report elements animate on first render:
- **Charts:** Bars grow upward from zero, lines draw left-to-right, pie segments sweep in. Powered by ECharts' built-in animation system.
- **Metric cards:** Numbers count up from 0 to their final value over 600ms.
- **Sections:** Fade in with subtle upward slide (`opacity 0->1, y 12->0, 300ms`) as they enter the viewport.
- **Tables:** Rows stagger in (`40ms` apart).
- **Key findings:** Accent border slides in from the left.

Animations play once on initial render. Scrolling back to an element does not re-trigger. PDF export renders the final state with no animation.

### Smart Number Formatting

All numeric values in metric cards, table cells, and cover stats are formatted using `Intl.NumberFormat`:
- Large numbers: `$124.3B`, `$3.02T`, `14.2K`
- Percentages: `+31.1%`, `-2.3%`
- Multiples: `32.1x`
- Currency: locale-aware with proper symbol placement

The LLM outputs pre-formatted strings (it decides the format as the analyst), but the renderer validates and normalizes formatting for consistency.

### Inline Colored Numbers in Text

Text blocks support a lightweight extension: numbers within body text that represent financial values are auto-detected and colored using `--report-positive` / `--report-negative` based on sign. For example, "revenue grew +31.1%" renders with "+31.1%" in green.

This is applied by the TextBlock renderer as a post-processing step on the markdown output — no schema change needed.

### Typography Details

- `font-variant-numeric: tabular-nums` on all table cells and metric card values for proper column alignment
- Proper em-dashes in text (LLM should use these; renderer normalizes `--` to em-dash)
- Superscript footnote reference numbers in table cells when footnotes are present
- `letter-spacing: 0.04em` on all uppercase labels (section headers, table group headers)

### Rating Badges

Colored pill badges for analyst ratings:
- Positive (Buy, Overweight, Strong Buy): green background, white text
- Neutral (Hold, Equal Weight, Market Perform): yellow background, dark text
- Negative (Sell, Underweight, Reduce): red background, white text

Used in the cover stats panel and as a standalone `rating_badge` block.

### Report Loading Skeleton

While the LLM generates the report, the FileViewer shows an animated skeleton that mimics the report layout (react-loading-skeleton):
- Cover area: large title skeleton, subtitle skeleton, metric card placeholders
- Section skeletons: heading bar, 3-4 text line bars of varying widths, a chart-sized rectangle, a table-sized rectangle
- Pulsing animation at `1.5s` cycle
- Section titles from the framework template shown as gray text above each skeleton section
